# Optional Actions-Rusher telemetry exporter
Disabled unless CISMON_TELEMETRY_DIR is set before launching. Use a new local directory with private ACLs; one CISmonWEB process per directory. For PowerShell: `$env:CISMON_TELEMETRY_DIR = "$HOME\.actions-rusher\cismon-telemetry"; npm start`. To disable: Remove-Item Env:CISMON_TELEMETRY_DIR, restart. No changes to monitor settings, history, provider rate, dashboard, API or credentials. No other repository's workflow records exported; heartbeat is pilot-scoped, although provider rate/error count is monitor-wide. No model dependencies. Do not expose journal externally. SHA-256 names retain equality, not anonymity.
Contract: https://github.com/techrote/actions-rusher/blob/mission/telemetry-001/docs/TELEMETRY-V1.md. Capture at accepted summary/detail and reconciliation, including 304 confirmations; heartbeat every 30 seconds. Raw provider state and effective execution state distinct. The per-scope analyzer results are retained; downstream can aggregate fresh active child attention. Does not claim dashboard aggregate classification or complete provider visibility. Monitor's bounded scans are not expanded. Older terminal detail captures can be retrospective provider facts first witnessed now. Unknown metadata remains absent.
Hourly JSONL files, newline separation for torn tails, single asynchronous writer, 4 MiB queued, 32 MiB hourly ceiling, 2,000 rows/run projection, explicit export-gap on next successful write. At saturation data is dropped rather than changing poll scheduling. A crash before flush may lose buffered rows; session-start marks restart, not exact loss. Hour-granularity 30-day exporter cleanup; Actions-Rusher performs exact rolling retention. Filesystem permissions on Windows rely on owner ACL. No claim of continuous completeness. Existing CI standard public runners exercise test and browser acceptance; no manual rerun or workflow edits.

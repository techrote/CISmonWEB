# CISmonWEB quality audit — 4 November 2026

## Scope and source

This pass reviewed the local Node HTTP server, configuration and timing
persistence, GitHub scheduling and reconciliation, run-attempt lifecycle,
dashboard analysis, and browser configuration/detail interactions. It implements
the reproducible defects below and records the boundaries that remain.

The source baseline was:

- Existing draft [PR #17](https://github.com/techrote/CISmonWEB/pull/17):
  `b32db852a06f8d0e50add761d78a2dde1b5f9307`.
- Integration branch: `fix/quality-audit-20261104`.

The audit branch includes PR #17 by ancestry, preserving its duration-unit
wrapping and Surface fullscreen work. PR #17's physical Firefox acceptance gate
is not waived by this audit. Neither the main branch nor the original PR branch

The inherited PR #17 source passed **113 tests** before this work. That green
baseline did not cover the failures reproduced here. The combined audit adds
**53 regression tests**, for **166 passing tests** under local Node 24.22.1.
The repository's existing CI runs `npm test` and `npm run check` on Node 22;
the audit PR's check records provide the authoritative remote result and SHA.

## How failures were qualified

Regression tests were written and executed against the inherited source before
their respective fixes. The initial history/lifecycle set reproduced 13
failures, the initial monitor set reproduced ten, and the initial UI set
reproduced six. The configuration and HTTP tests also reproduced their storage,
encoding, origin-boundary and asset-failure defects before repair. Additional
cases verify retry paths, compatibility and interactions among the fixes.

The tests use three kinds of evidence:

- **Deterministic provider responses:** exercise pagination, omitted runs,
  authoritative terminal status, 404/transient failures, changed attempts,
  old responses after a provider reset, visibility and rate scheduling.
- **Real temporary files and local HTTP subprocesses:** verify committed
  configuration snapshots, rollback, interrupted journals, split UTF-8 bodies,
  byte limits, host/origin rejection and server survival after asset failure.
  Credentials in these tests are artificial fixtures.
- **The actual browser application module under a controlled VM/DOM harness:**
  reproduce delayed-response order, rapid surface changes, simulated HTTP 500,
  detail selection/close and late action completion. This qualifies event/state
  behavior, not browser layout or native fullscreen chrome.

The final combined local suite passes **166/166**, with no skipped tests.
`npm run check` passes for **28 JavaScript files**. `git diff --check` passes.
The existing CI definition and runner matrix are unchanged; no runtime npm
dependency was added.

Independent review of the history/tracker implementation found no blocking
defect and identified the downgrade and partial-history limitations documented
below. Independent review of the monitor implementation checked generation
guards, request fairness, omitted-run freshness, retry behavior and attempt
binding; terminal bookkeeping and check-target lifetime were then explicitly
qualified before integration. The integration owner also reviewed the server
and browser diffs and reran the combined suite after bringing them together.

## Existing duration and popup work

PR #17 inserts discretionary breaks between complete duration units in Wrap
mode, so `22m16s` can become `22m` followed by `16s`. It avoids arbitrary splits
inside `16s`, preserves the underlying text and sort values, and leaves the two
Clip modes independent. This work remains in the consolidated audit branch.

The misleading **JS popup (no address)** experiment is replaced by **Surface
fullscreen**. A regular Popup remains subject to browser chrome rules. Surface
fullscreen requests native fullscreen and a surface-only layout; it fills the
monitor rather than providing a separately resizable chrome-free window.

Actual graphical acceptance was attempted but could not be completed here.
The available Chromium process was blocked at socket creation. The cached
Firefox/Playwright combination could not establish a compatible page, and a
bounded native Firefox screenshot attempt failed when sandbox child processes
could not set up their user-ID mapping. No screenshot or visual pass is claimed,
and browser sandbox controls were not weakened.

Before integrating the consolidated branch, verify on the intended Firefox
installation:

1. At a 40px duration column, Wrap keeps `22m` and `16s` intact; check ELAPSED,
   MED, ETA and S-ETA, including `WAIT` and `≥` prefixes where present.
2. Both Clip modes still behave as configured, and ordinary separator wrapping
   remains independent of duration-unit wrapping.
3. Surface fullscreen enters from a user click; Escape and Exit surface-only
   restore the appropriate app layout. A regular Popup is still usable.
4. Resize a column and switch surfaces quickly; return and reload to confirm
   the width persisted. Open/close details and use Watch/ACK normally.

Automated event-order tests cover the fourth item's underlying races, but do
not replace physical keyboard, layout and native browser behavior.

## Compatibility and remaining limits

- **Existing credential files:** this fixes future environment-token copying.
  It cannot identify whether an old stored token was intentionally saved or
  copied by the previous bug. Configure shows both token sources. Clearing the
  stored token while an environment token is active leaves that environment
  token in use. See [Security notes](SECURITY.md).
- **HTTP clients/proxies:** writes require `application/json`. Origin must
  agree with the trusted upstream authority; a rewriting or TLS-terminating
  proxy must normalize those headers and retain its own authentication. Host
  and Origin checks are not a network authentication system.
- **Journal compatibility:** new readers accept old flat and new grouped
  entries. Old readers ignore the grouped samples. Copy the data directory
  before downgrading. Legacy completion markers do not carry an attempt and
  are interpreted as attempt 1; existing history is not rewritten or discarded.
- **Partial history:** historical detail is still limited to one 100-job page.
  An incomplete/unsettled observation may record individual completed jobs
  without a workflow sample. It is marked recorded and is not automatically
  upgraded later. Live scans still have the existing 20-page limit.
- **Discovery bounds:** repository discovery still considers the first 100
  returned repositories, with configured filtering and cap; activity admission
  probes ten recent workflow runs. Direct reconciliation fixes already tracked
  runs that later leave the 100-run list; it cannot discover every old run that
  was never observed.
- **Unavailable runs:** a 404 or permission error does not establish a terminal
  conclusion. The monitor retains a last-known state with stale/degraded
  confirmation instead of claiming cancellation or completion.
- **Storage/session limits:** samples per key are bounded and journal reading
  is streamed, but distinct timing keys, attempt markers and the journal file
  are not globally capped or compacted. There is no cross-process writer lock;
  run one process per data directory. Watch/acknowledgement and retained failure
  state remain session memory.
- **Multiple windows:** the queue repairs races within one browser page.
  Concurrent bulk surface edits from separate windows remain last-writer-wins.
- **Platform/live acceptance:** local verification used Linux and synthetic
  provider responses. A live authenticated monitoring session, physical Windows
  filesystem behavior, graphical Firefox layout and native fullscreen remain
  outside the completed qualification.

No GitHub workflow was cancelled, rerun or changed as part of this audit. No
release or deployment is created, and the preserved physical acceptance gate
remains explicit in the audit pull request.
